# 安全模型

NeuroKiln 是**单机科研工具**，不是多租户服务。完整策略见仓库根目录 `SECURITY.md`，本页说明使用与部署时必须理解的事实。

## 1. 账号与令牌

- 密码使用 PBKDF2-HMAC-SHA256 + 每用户随机盐存储，不保存明文。
- 首次启动通过初始化接口创建本机管理员，仓库不包含默认账号或硬编码密码。
- 登录令牌是 HMAC-SHA256 签名的 Bearer Token，签名密钥在首次启动时随机生成并写入 `data/.auth_secret`。
- 除 `/api/health` 与登录 / 初始化接口外，所有 `/api/*` 都需要有效令牌；用户管理、清空缓存、安装 / 卸载插件、删除实验或自定义丹方、覆盖已导入数据集等操作仅管理员可用。
- 令牌默认 12 小时过期，没有吊销列表；浏览器把令牌保存在 `localStorage`，因此前端 XSS 会直接暴露令牌。

## 2. 数据与网络暴露

- 默认只绑定 `127.0.0.1`。不要把 API 直接暴露到公网；如需远程访问，请放在带 TLS 与身份认证的反向代理之后。
- SQLite 数据库不加密。敏感数据应放在全盘加密或受控卷上，并限制 `data/` 的文件系统权限。
- 没有内置速率限制或账号锁定；不要把它当作公网服务。
- 导入文件有 2 GiB 上限；NPZ 以 `allow_pickle=False` 解析；EDF/FIF/CSV 由 MNE 或内置解析器读取。
- 报告与实验库不写入原始可识别被试信息，但数据本身的伦理与脱敏责任在使用者。

## 3. 插件执行

| 模式 | 行为 |
|---|---|
| 默认（受限） | 只加载声明式图插件，不执行第三方 Python |
| `NEUROKILN_PLUGIN_TRUST=1` | Python 插件在 API 进程内执行，**没有沙箱、没有权限隔离** |

- 安装时校验清单、文件后缀、数量、大小、路径与 SHA-256，拒绝 zip-slip；启用时重新校验。
- 复现时若插件缺失、版本不同或包哈希不一致，系统拒绝运行，而不是静默替换。
- 只安装你已逐行审阅过的插件。可信模式下的插件可以读取本机文件、访问网络、消耗进程资源。

## 4. 已知限制

- 前端 XSS 可导致令牌泄漏；请及时更新依赖。
- 无令牌吊销列表与账号锁定。
- 数据库未加密。
- 第三方数据集（如 MOABB）的完整性与许可证由上游负责。
- 在线 / 闭环模块只提供协议与离线回放，不含实时设备驱动，也不构成临床或在线性能保证。

## 5. 报告安全问题

仓库发布后，请优先使用 GitHub Security Advisories 私密报告；若不可用，先联系 `CITATION.cff` 中的维护者，不要公开披露细节。报告请包含受影响版本、复现步骤、影响范围，以及是否需要登录或可信插件模式。我们目标在 7 天内确认、30 天内为已确认问题提供修复或缓解。

## 6. 部署清单

- [ ] API 只绑定 `127.0.0.1`，或置于 TLS + 认证反向代理之后
- [ ] `NEUROKILN_PLUGIN_TRUST` 未设置（除非你完全信任已安装插件）
- [ ] `data/` 权限受限，`neurokiln.db` 与 `.auth_secret` 一起备份
- [ ] 使用强密码，定期轮换；不要把令牌写入脚本、日志或仓库
- [ ] 发布派生结果前核对数据集许可证与引用要求
- [ ] 不上传可识别被试的数据到公开 Issue
